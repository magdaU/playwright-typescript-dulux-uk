## Open items

- [ ] **Cookie-consent banner intermittently reappears despite `storageState`.** First seen while building
      `tests/specs/search/colour-search.spec.ts`: a run against production failed with the OneTrust consent
      overlay (`onetrust-pc-dark-filter`) blocking a click that should've been well past consent (storage state
      is regenerated by `tests/setup/global-setup.ts` before every run). A retry with identical setup passed
      cleanly. **Seen again** while building `tests/specs/visualizer/visualizer-app.spec.ts` — both desktop and
      mobile runs failed on the same overlay on the first attempt, then passed cleanly on retry. Two independent
      occurrences confirm this is a genuine, intermittent flake in production's consent tooling (not a bug in
      either new test), and it affects any spec that relies on the shared `storageState` (i.e. the whole suite).
      **Why not fixed now:** each occurrence was out of scope for the PR that hit it; needs its own investigation
      rather than a silent workaround bolted onto individual specs.
      **Suggested next step:** add a shared, defensive "dismiss consent if present" helper (e.g. on `BasePage`
      or as a fixture-level `beforeEach`) so any spec recovers instead of failing outright — then decide whether
      that's enough, or whether `global-setup.ts` itself needs a retry/verification step before persisting
      `storageState`.
